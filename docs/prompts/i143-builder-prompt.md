## 你的问题不是"它自由吗"

**两个答案都不预设。** #78 的审计小心地区分了*"我没找到约束"*和*"不存在约束"*，这根棒继承同一条纪律。

## 🔴 会对你撒谎的那个仪器

这是本任务书里最重要的一段。#78 的审计产出了一条方法论发现，**在这里直接适用**：

> *"那个测试测的是**「这个格子是否出现在某条活约束里」**，不是**「约束系统是否决定这个格子」**。每个派生/累加列都读它的输入，所以篡改输入**总会**打断输出的定义约束 —— 而那**正是**「自由 witness 喂给一个被钉住的累加器」这个情形。"*

`S`/`V`/`U` 是移位寄存器，**第 0 行之后每一行**都被它们的 transition 钉住。所以篡改第 0 行会打断 row0→row1 的 transition 并读出 UNSAT —— **而那关于"第 0 行是否被决定"什么都没说。** 一个 prover 选了第 0 行，然后让后续每一行一致地跟着走，那是一条**合法的 trace，不是一条坏掉的**。

**如果你因为"篡改打断了什么"而得出"被绑住了"，你就是把那个假阴性复现了一遍。**

诚实的仪器是两个：**扰动后重传播**（扰动第 0 行、重跑 fill 让整条链跟着、**然后**才检查），或**静态的决定性位置分析**（对该列在 `eval` 里的每一次出现，问它是否处在**决定性位置** —— `assert_eq` 的目标、`assert_bool`、gated pin、first-row pin、transition carry —— 而不只是被读）。

## 一个区分，别把两者当同一件事

**存在于 AIR 里的绑定**值一个价；**只因为调用方碰巧传了零而存在的绑定**值得少得多。所以除了 `narrow.rs`，还要看**共识调用路径** —— `qlab_consensus::verify_proof` 到底把什么作为初始状态传进去。

## 三种结局，交付物不同

- **绑住了** → 一个"若移除该绑定就会挂"的测试，加 `narrow.rs:44-48` 一行文档点名是哪条约束。**现在那段文档解释了这一列为什么自由，却没说是什么让它安全 —— 设计注释和约束不是同一个物件，而只有其中一个会被任何东西检查。**
- **没绑住** → 🔴 **停下并报告。不要凭自己的判断去改一个 FROZEN 的共识 AIR。**
- **判定不了** → 说出来，说清你读了什么、没读什么，并点名能settle 它的实验。#78 的审计就是范本：*"我没看到任何一条挂掉，因为我一个测试都没跑"* 比一个自信的猜测是更好的报告。
