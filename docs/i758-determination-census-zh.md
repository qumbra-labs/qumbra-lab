## 1. 方法与校准

**要回答的问题。** 诚实 trace 里的每个格子、每个公开值，是不是都由 witness manifest 里的输入（"源"）唯一决定？约束管不住的格子就是第二类自由度。它碰得到公开值时才要紧。

**引擎**（`qlab-air::detaudit`，feature `audit`）分几层：

- **L2，普查：** 从源出发做前向不动点。
  - 规则：系数非零的仿射；布尔量的唯一根；有界变量上的超递增重组；以及*极值*求和（系数同号，目标取 0 或取最大值）。
  - 布尔分情况：两个未知量，布尔量取两个值时根都一样。
  - 线性消元：别名、小方程组、以含有界未知量的方程为种子的 200 类邻域。
  - **有界枚举**（R11）：逐行把卡住的、读到公开值的方程分组。布尔未知量不超过 12 个的组，把所有布尔赋值都试一遍，其余未知量逐情况解出，数合法解有几个。只有一个解，整组就定了；两个以上就记成 `AMBIGUOUS`，同时列出哪些公开值不同。
  - witness 副本必须经由它的绑定重新推出来。
  - 较晚才确定的公开值会重新唤醒读它的约束。
- **L3，确认：** 推不出来的格子分成连通分量。先用单格排序找出每个分量的根，再翻转这个根、重放它的下游锥（必要时重新求解绑定），其他根保持不动。
  - **可满足与否由 p3 的 `check_constraints` 在完整修复后的 trace 上独立检查。**
  - **只有"可满足"才算证据。** 其他根固定时得到的"不可满足"并不构成反驳。
- **L1，静态角色普查**（定向关系，以及每个被消费格子的读者），加上**空转检查**：在被审计的 trace 上既不承重、也不起限制作用的约束。

**校准：**
- 在一个 AIR 里重新植入一个已知的历史缺陷，普查抓到了它：可满足、公开值被改动，p3 的独立检查也吻合。**校准：植入缺陷捕获 = 是。**
- 协调者在不告知构建者的情况下放了三个**盲植缺陷**：
  - 缺陷 1 在 claim 上：抓到，可满足，公开值被改动；
  - 缺陷 2 在 claim 上：抓到，可满足，公开值被改动；
  - 缺陷 3 在 narrow 上：抓到（有 flag，根也点了名）。它所在的分量有 4300 万个格子，确认没有跑完，这是记录在案的局限（§4）。
- toy 装置（`--toy`，以及用于枚举的 `--sign-top` / `--sign-wrap`）作为自检在本地跑。
- 单元测试把这些控制钉住：`detaudit_rig_*` 和 `detaudit_sign_chain_enumeration`，在 CI lane 上跑。

### P3：结论是怎么得出的（R8 → R15）
从 R8 到 R15，这些运行一步步确立了结论：

1. **比较行的可变性。**逐位比较器空闲 T 行上约 100 万个单行 flag（`CMP_OFF…`）。确认可满足且没有公开值变化（R6b，8/8）。**设计如此。**
2. **vPublic：没有增发。**
   - 把所有公开值都当作输出（`--no-pv-inputs`）时，house 推不出来的 vPublic 恰好是 **[100, 105, 106, 111]**，即每行金额为 0 时的 `redeem` 和 `vpa`（R11）。

   - `--confirm-pv 107`：没有 flag 碰得到它。
   - **金额和正负号都由 witness 唯一决定。**
3. **anchor 和 cm。**不加抗碰撞前提时，普查卡在第一个 `ARKM′`：第 141,312 行，即第 46 段。`ARKM′`/`ARKM″` 把 `nk` 当作自由输入，只靠输出绑定（§3），所以它下游的一切看上去都是自由的。
   - **加上 `--cr-premise` 后：**
     - house：推不出来的是 **[100, 105, 106, 111]**；
     - mint 和 redeem：**[100, 105]**（R14）。
   - anchor 和 cm 都**被确定**。
   - 剩下的 flag **碰不到任何公开值**：
     - END 之后的填充区（§4）；
     - 975 个格子的 W+比较器碎片。
4. **绑定探针**（`--probe-arkm2`，R14）。把吸收行上的某个副本翻转一位，重放它的下游锥。**每个副本都被拒绝：没有 `NOT TIED`，没有可满足。**归因如下：

## 3. 前提（用到它的运行都会打印出来）

1. **公开值范围**（`audit_pv_bits`）：每个公开值都是 16 位分块，例外是 P3 的 `redeem`（1 位）、`vpa`（32 位）和 R 的资产号（32 位）。这就是验证方自己的构造方式（`pv_chunks`/`pv_vec*`），`qlab_l2::verify_*` 和 claim 会拒绝超出这个范围的向量（`pv_in_range`、`ClaimRefusal::PvRange`；CI 测试 `l2_pv_range_premise_holds_and_is_enforced`）。**L1 冻结的验证入口将另行收窄**（后续 PR）。
2. **P3 金额为 0 时的 vPublic 字段对**（`l2p::audit_pv_inputs`）：某一行金额为 0 时，它的 `redeem` 和 `vpa` 被声明为输入。
   - `qlab-devnet/src/annulet.rs:233` 在验证任何证明之前，就拒绝 `amount == 0 && (redeem || asset != 0)`（`NonCanonicalZeroTerm`）。
   - **路径：**构造 P3 公开值的共识路径只有一条：`qumbra-node/src/verifier.rs:123`（`L2Surface::decode(&entry.l2)`，其中 `TxEntry.l2: Vec<u8>`），然后第 181 行用解码出的条目调用 `pv_vec_p`。
   - `qlab_l2::verify_p` 本身接收原始公开值，**不**做规范性检查。它的其他调用方只有 bench 和测试。将来若有调用方绕过解码，就失去了对零额条目的钉定。
   - 金额分块从来不被声明为输入。
3. **抗碰撞**（`l2p::audit_cr_premise`）：`ARKM′`/`ARKM″` 处的 `nk` 被声明为源。
   - 它只靠输出绑定：第三个 bank 上的 `rkm@AFKEY − rkm′@ACRED`（在 ACRED 结束处收口），以及 bind bank 上的 `rkm′@ACRED − rkm″@ACM`（在 ACM 结束处收口）。
   - 用另一个 `nk` 算出同一个 `rkm`，就是 Keccak 的原像或碰撞，这不在普查的代数范围之内。
   - 其他所有副本都由某个 bank 绑到一个前向算出的值上，**不**在这个前提之下。
4. **诊断前提。**每一个都会在输出里标 `⚠️ DIAGNOSTIC`。
   - **`--pin-cmp`**（把比较器的格子声明为源）：**不用于任何结论。**
   - **`--pin-sel2`**（把输出记账开关 `o1a`/`o2a` 声明为源）：只用于 P3 merge 那几行，而且**只与**对这两个开关本身、**不固定时**的翻转确认**一起**使用：`o2a`（R14 flag 3、R17a/b flag 3）和 `o1a`（R18a/b），每个都**可满足且公开值不动**，p3 独立检查通过。
     - **为什么两者合起来就够了：**固定把两个开关钉在诚实值上，此时所有公开值都被确定；翻转说明每个开关取另一个值时也能得到可满足的 witness，而且公开值**完全相同**。所以开关怎么取都到达不了不同的公开值，钉住时得到的确定性对所有 witness 都成立。
     - §2 P3.6 的代数论证（`BL + BL2` 的转移与开关无关；`q` 下只有求和链生效）从约束的角度说明了同一件事。
