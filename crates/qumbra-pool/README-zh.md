**08-23 那次停摆值得记,因为这个失效形状会重演。** `tiny_http` 在超过
`chunked_threshold().unwrap_or(32768)` 时切到分块传输(`response.rs:246`),而
`chunked_transfer::Encoder` 每块 8,192 字节 —— 十六进制正是 `2000`。矿池的 node RPC 客户端
把 `\r\n\r\n` 之后的字节原样交给 serde,serde 于是把**分块长度那一行**当成了整个文档:


也就是说,只要模板超过 32 KB,矿池就什么都服务不了。**PR #628 把成帧提升进
`qlab-http-framing`,并修好了全部四个手搓客户端**,不只是这一个 —— 同样"取头之后的字节"
那个形状在另外三处也在。滚过之后活体核过:在服务,零解析失败。

### 🔴 为什么现在还不能邀请第二个矿工 —— 收款人上限

**今天一个块只能付给一个地址,而矿池把整份奖励给这个地址。**

```rust
// crates/qlab-devnet/src/body.rs
pub const COINBASE_PAYEE_CAP_V5: usize          = 8;
pub const COINBASE_PAYEE_CAP_V5_AT_BIRTH: usize = 1;
pub const COINBASE_PAYEE_CAP_V5_BOUNDARY_HEIGHT: Option<u64> = Some(11_520);
```

T2 在 2026-08-24 15:49 +08 实测 **tip 4,802**(`explorer.qumbra.org/v1/health.json`),所以
生效上限是 **1**。`payee::pick_payees` 于是把 PPLNS 窗口按权重排序、截到上限,把**整份**产出
交给第一名:

```rust
scored.sort_by(|a, b| b.1.cmp(&a.1));
scored.truncate(cap);
if scored.len() == 1 || cap == 1 {
    return vec![CoinbasePayee { rkm: scored[0].0, amount }];   // 全额
}
```

**这是已知且刻意的状态,不是缺陷** —— `payee.rs` 的模块注释写着 *"Before activation, PPLNS
cannot split the mint"*,对应的测试就叫 `v5_birth_cap_is_one_so_the_winner_takes_the_mint`。
### 🔴 它不是假设 —— 从 2026-08-22 12:19 起就一直在发生,而且比"小矿工吃亏"更糟

**我们自己的两个矿工已经同时挂在这个矿池上超过 23 小时** —— `hel1` 上两个 stock XMRig 进程、
两个不同的收款登录、**同样的硬件、同样的二进制、各一个线程、各约 27 H/s**。累计被接受的份额
相差 **2%**(2,730 对 2,783)。两把钥匙都在两台矿机连上**之前**就发布在 lab #553 上,各自带
全链缺席证明 —— 所以下面的身份认定不依赖任何人的一面之词。

**它们各自挣到了什么:**

| 窗口 | | |
|---|---|---|
| 2026-08-22 约 17:47,60 块 | `m2` = **28** | `m1` = **3** |
| 2026-08-22 约 22:19,60 块 | `m2` = **0** | `m1` = **32** |
| 2026-08-24,最近 120 块 | `m2` = **55** | `m1` = **1** |

**两个体量完全相同的矿工,轮流把对方封杀几个小时。** 收款在那个尾随 1,024 份额的 PPLNS 窗口
翻转时易手,而在翻转之前领先者拿走**全部**。某个时刻 `m2` 做的总功比 `m1` 还多,而它从当天
下午起一分钱没挣到。

**所以"小矿工挣得少"是低估,而且是朝着误导的方向低估。** 那种说法诱导人以为只是边际上的
比例失真。**实际发生的是势均力敌者之间的赢家通吃**,以小时为单位轮班,输的一方的电白烧到
窗口翻转为止。**那才是一个陌生人会加入的东西。**

**从来没有任何陌生人在这个矿池上挖过** —— 两个登录都是我们自己的,这也是迄今为止这件事
没让任何人蒙受损失的唯一原因。

### 🔴 那道边界是一次全舰队共识滚动,而邀请第二个矿工正是引爆它的动作

引自那个常量自己的文档注释:

> **这是一次共识规则变更,滚的是整个舰队,不是一台。** 边界之上一个块可以带多个收款人;还在
> 旧二进制上的节点会拒收这种块并分叉出去。跟 8,640 那次排放边界不同,**这是无停机穿越**,
> 所以没有停机来接住掉队的 —— 每一台做验证的主机都必须在 `11_521` **之前**带上这个常量。

**实际风险窗口比规则窄,而这恰恰是陷阱**:要等到真有一个块写进两个或更多收款人才会分叉,
**而那只在 PPLNS 窗口出现两个以上赢家时发生。** 也就是说,"第二个矿工加入"和"分叉变得可能"
是同一件事。顺序不能反。

**跑道**:11,520 − 4,802 = **6,718 块**,按 75 秒目标 ≈ **5.8 天** —— 边界落在 **2026-08-30**
前后。这个余量是刻意留宽的,而且它是从一个会动的 tip 上量出来的。

**在那之前欠的一件事,而且它是主机上的读数、不是仓库里的读数:确认六台主机上在跑的二进制
都带着 `Some(11_520)`。** 文件里有、进程里没有 —— 这个失效这个项目已经付过一次学费了。

### 🔴 可达性 —— 端点对公网开放,而且在服务

**2026-08-25 11:25 +08,从舰队之外一台普通笔记本上实测。** 一个用任意名字发出的 stratum
`login`,拿回了**针对真实高度的真实任务**:

```
nc -vz 54.243.254.140 3333   ->  succeeded

{"id":1,"jsonrpc":"2.0","result":{"id":"s00000012","job":{
  "algo":"rx/0","height":5737,"job_id":"j00000fae",
  "blob":"1591123cb6e4…","seed_hash":"d1e28adcce8f…"}}}
```

**今天,任何知道这个主机名的人都能连上并拿到活。** `pool.qumbra.org` 解析到
`54.243.254.140`(AMAZON,纯 DNS —— 前面没有 Cloudflare,和 `seed.qumbra.org` 不同),
而从公网到 stratum 端口之间,没有任何东西会拒绝一个陌生人。

> ⏳ **更正,2026-08-25。** 2026-08-24 合进来的那一版说的是**相反**的话 —— 说 TCP 3333
> *"超时"*、说*"静默是安全组 DROP 的签名"*、并据此说外部探针分不出在跑的矿池和停掉的矿池。
> **那些全是假的。** 它立在一次探测上:
> `bash -c 'exec 3<>/dev/tcp/pool.qumbra.org/3333' 2>/dev/null` —— 这个构造打这个端点会**挂住**,
> 被它自己的 `timeout` 杀掉,而 stderr 被丢弃了,于是那份静默被读成了关于服务的事实。
> 第二天带对照重跑就结了:同一个构造打 `seed.qumbra.org:443` 立刻返回,所以 `/dev/tcp`
> 在这里是好的,失败是那次探测特有的。**`nc` 和 stratum 登录两条都成功。**
>
> 教训是这个仓库反复付学费的那一条:**一个静默失败的探针,和一个宕掉的服务,是同一个读数。**
> 在一个会挂住的探针上抑制 stderr,就是把"我的仪器没工作"变成"那个东西不在那儿"。

**所以挡在陌生人和这个矿池之间的,只剩"没有公布"这一件事 —— 而这份文档自己写着默默无闻不是
一道控制措施。** 那句话原本是针对端点被停掉之前那段暴露窗口写的;端口重新开着,它原样适用。

**结合上面的收款人上限,这在今天意味着什么:** 一个连进来的陌生人会拿到几小时的全部产出和
几小时的零,和他那段时间贡献了多少无关。**挡着他的不只是"还没公布"这道门 —— 本该是安全组,
而它没有收窄。**

> 通过之前收窄安全组;该建议被否决,这是刻意的立场,不是疏忽。
>
> **它接受了什么:** 端口对公网保持可达,唯一的保护是主机名没有公布 —— **而默默无闻不是一道
> 控制措施,这份文档往上两段就是这么写的** —— 而一个真的连进来的陌生人会撞上 cap-1 的收款方式,
> 没有任何东西告诉他这是预期行为,而且这个矿池
> [记不下他是谁](https://github.com/qumbra-labs/qumbra-lab/issues/584)。
>
> **什么给它划了界:** 收款人上限在高度 **11,520** 按规则结束,决定作出时还差

## 这个矿池不一样在哪

传统矿池收到出块奖励,然后**欠**矿工各自的份额。这笔债就是矿池的权力、也是矿工的风险:
从出块到打款之间,你的收益由矿池托管;矿池跑路,收益跟着走。

Qumbra 的出块奖励是**写进共识的收款人列表**(`CoinbasePayee`,T2 的 v5 body 形式)。
**区块本身**在被接受的那一刻直接付给每个矿工。**矿池从不持有矿工的钱**——它只决定
份额、组装区块,付钱的是链。运营者中途消失,你损失的是这一轮,不是你的余额。

✅ **以上是设计,而从 2026-08-22 01:19 +08 起,它也是这个矿池在做的事。** 高度 1776 付给了 `daf76f16…` —— 矿工自己的密钥,在 tip 1771 时公开贴出,比矿机连上早 13 秒,并已证明在此前全部 1,772 个高度中一次未出现。4.992690888 QMB,由链支付,矿池从未持有。

**下面保留作废的 🔴 段落,因为一份把自己曾经的状态删掉的文档,教不会任何人当初错在哪:**

> 🔴 **以上是设计。它不是这个矿池今天在做的事。** `GET /v1/mine/template` **报告**收款人,
> 不**接受**收款人——而收款人被绑进了矿工据以计算的区块头,所以 share 回来之后无法替换。
> **这个矿池能提交的每一个块,都付给 poolnode 的 `miner_rkm`,与 PPLNS 窗口说什么无关。**
> `payee::assemble_coinbase`(选 winner、空窗口兜底、上限)本身是正确的,但它**不在提交路径上**
> ——它的消费者只有一个只读访问器和两个单元测试。**所以矿池现在是托管式的:它把 coinbase 挣到
> 自己地址上,而没有任何机制付给任何人。** 追踪于
> [lab #553](https://github.com/qumbra-labs/qumbra-lab/issues/553),它是这个端点能否对外公布的闸。
> 
> **这是实测,不是推断**(2026-08-21,首次实盘):一台矿机用一个**链上从未被挖过的**收款地址
提交了 29 份被接受的 share,全程都在 PPLNS 窗口内。那个窗口里落了三个块。
**三个全部付给了矿池自己的地址;矿工的钥匙拿到零。**

**再一次实测,这次是规模上的**(2026-08-22,`1772..2095`,**324 个高度全部核实覆盖**,两把密钥都按完整 32 字节比对):

| 收款人 | 区块数 |
|---|---|
| `daf76f16…` —— 矿工的密钥,**在 tip 1771 公开,比它的矿机连上早 13 秒** | **137** |
| `5f13e0c7…` —— 一个 solo 矿工 | 39 |
| `d2c02c7c…` —— 一个 solo 矿工 | 33 |
| **`79c3291d…` —— 矿池自己的兜底地址** | **0** |

**那个零是更锋利的一半。** 兜底不是在统计里输了,而是**从来没有被走到过**。而且这一轮自带一个计划外的**阴性对照**:在矿机算力为零的 52 分钟窗口里,它的密钥在 33 个块中拿到 **0**,矿池也一个块都没出——**付款在两个方向上都跟着真实工作走**。137 这个数**跨过了那个死窗口**,所以它低估了挖矿时的速率,**绝不能当成算力份额来读**。

这正是收款人列表 coinbase 存在的全部理由,也是这个 crate 值得读而不只是值得跑的原因:
**任何人都可以运营一个**,而这个设计只有在不止一个人这么做时才有意义。

## 形状

```
  XMRig ──stratum/TCP──▶ qumbra-pool ──HTTP──▶ qumbra-node ──▶ 链
        login/job/submit              GET /v1/mine/template
                                      POST /v1/mine/block
```

- **矿工侧**:普通的 Monero 家族 stratum,stock XMRig 不改一行就能说。协议是什么见
  [`docs/stratum-primer-zh.md`](../../docs/stratum-primer-zh.md),逐字段映射(含具名偏差)见
  [`docs/pool-stratum-mapping-zh.md`](../../docs/pool-stratum-mapping-zh.md)。
- **链侧**:矿池向**自己的**节点要区块模板,并把完成的区块交回去。两条路由默认关闭,
  需要节点配置里 `template_serving = true`——运营者跑自己的节点,自己打开它。
- **share 校验**用 `qlab_devnet::pow::satisfies_target_for`——**与共识同一个谓词**——
  配 v5 的后 8 字节小端工作量取值(lab #490)。share 过滤用 XMRig 的严格 `<`,块候选用
  共识的 `<=`;这个差别是刻意的,并有测试锁定。
- **记账**是 PPLNS,窗口为最近 `PPLNS_WINDOW_SHARES = 1024` 份被接受的 share
  (`[devnet-placeholder]`,不是冻结参数)。

## 配置

带注释的完整示例见 [`qumbra-pool.example.toml`](qumbra-pool.example.toml)。要紧的字段:

| 字段 | 含义 |
|---|---|
| `listen_addr` | stratum 监听地址,`3333` 是惯例 |
| `share_difficulty` | 发给矿工的 share 目标;按设计低于链难度 |
| `node_rpc` | 你自己节点的 mine-RPC 地址。**这才是真正的模板源。** |
| `poll_ms` | 多久向节点重新要一次模板(默认 1000 ms)。tip 变化时矿池替换持有的模板、把未完成的 job 标陈旧,并向每个在线会话 **推送一条 `job` 通知** |
| `template_max_poll_failures` | 连续失败多少次 poll 之后暂停发活(默认 3) |
| `template_max_age_ms` | 多久没有一次成功的 poll 就暂停发活。不设时等于 `template_max_poll_failures × poll_ms`,跟着 poll 节奏走,而不是另写一个数字 |
| `template_disconnect_after_ms` | 持续多久拿不到好模板后才结束已暂停的会话,让矿工切换备用矿池(默认 300000 ms / 5 分钟)。必须大于暂停阈值 |
| `payout_rkm` | 矿池自己的收款身份,来自 `qumbra-wallet miner-rkm` |
| `max_connections` | 同时在线的 stratum 连接数(默认 64)。每个连接是一条线程;超过上限时 accept 循环写 `connection-cap-reached`,不再 spawn |
| `max_connections_per_ip` | 同一 IP 的同时连接数。不设时等于 `max(1, max_connections / 8)`,一个对端占不满整个上限 |
| `max_line_bytes` | 一行(含换行)的最大字节(默认 4096)。超过就以 `line-too-long` 断开 |
| `request_timeout_ms` | 从一行的第一个字节起,写完这一行的墙上时钟(默认 10000 ms)。和用来排空 job outbox 的 100 ms 每次 read 超时不是一回事;慢速逐字节的客户端是这条在关 |
| `connection_timeout_ms` | 从 accept 到第一条完整行的墙上时钟。不设时等于 `request_timeout_ms`。出过完整行之后,沉默的是在算的矿工,不会被踢 |
| `[template]` | **静态 fixture,仅供测试**——见下面的拒绝 |

### 两条你应该期待、也应该想要的拒绝

一个**看起来活着、实则毫无用处**的矿池,比一个起不来的矿池更糟——因为矿工在为它烧真实的电。
所以在监听端口绑定**之前**:

- **静态 `[template]` 会被拒绝服务**(`static-template-source-refused`)。固定的高度和 prev
  可以看起来完全健康,却根本没在跟踪任何链:活照发、share 照记,而其中没有一份可能变成区块。
- **全零或不可用的 `payout_rkm` 会被拒绝**。付给空身份的 coinbase,**谁也花不了**,
  包括挣到它的矿工。

`check` 和 `run` 都会走这两条闸,在任何 RPC 连接或端口绑定之前。
*(随 lab #519 的第一个 PR 落地;这里写出来是因为它是既定契约,不是可选项。)*

## 怎么跑一个

```sh
qumbra-pool check --config pool.toml   # 检查配置、拒绝闸、模板源——不开监听
qumbra-pool run   --config pool.toml   # 开服
```

你还需要一个**自己的** `qumbra-node`,并打开 `template_serving = true`。mine RPC 按设计
只在容器内可达:矿池经私有网络访问节点,而**节点的 mine 路由永远不对公网发布**——
对外的只有 stratum 端口。
